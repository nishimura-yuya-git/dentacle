# Symptom Hard Gate（症状ゲート）

Context Budget で must。Bug Fix Loop の完成ゲート。

発生源: 2026-08-25。「終日いけないを押すと配置がガクガクする」に対し、`ReferenceError` という
技術的な代理症状に言い換え、console エラーなしと `tsc` pass を根拠に「解消」と報告した。
差分ゼロのまま3往復し、ユーザーが同じ指摘を4回した。

## 完成禁止

欠落は `symptom-restated` / `symptom-measured` / `symptom-environment` / `fix-has-diff` /
`evidence-path-unresolved` で stop。

1. ユーザーの言葉のまま症状を書いていない（技術用語に言い換えた）
2. 症状を数値で前後比較していない
3. 「エラーなし」「例外が出ない」「テストが通った」を症状の解消根拠にした
4. ユーザーと違う URL・ポートで検証した
5. 「修正した」と書いたのに変更ファイルが無い
6. 実在しないキャプチャを根拠として貼った

## 症状の言い換え禁止

ユーザーの言葉が正。技術的な原因名は症状ではない。

| ユーザーの言葉 | 症状として書く | 代理にすると失敗する |
|---|---|---|
| 配置がガクガクする | ラベルのY座標が動く | `ReferenceError` が出る |
| 画面が飛ぶ | `window.scrollY` が変わる | HMR が古い |
| 表示がおかしい | 表示件数・文字・色の実測値 | 型エラーがない |

原因が症状を説明できるかは、原因を直したあとに症状を再測定して確かめる。

## 不在証明は測定にしない

「エラーが出ない」は、症状が消えたことの証明にならない。
症状が数値で表せるなら、必ず修正前と修正後の2つの数値を出す。

```text
症状測定: 終日いけないラベルのY 417 → 407（10px上昇）／修正後 417 → 417（差分0）
```

数値化できない場合は、キャプチャ2枚（前・後）を Read し、何が変わったかを1行で書く。

## 環境一致

ユーザーが見ている URL とポートで確認する。別ポートの結果でユーザーの報告を否定しない。
ポートが違うと分かった時点で、まずユーザーの環境に合わせ直す。

## 調査と修正を混ぜない

原因を特定しただけの段階では「修正した」「解消した」と書かない。
その段階の報告は「原因の仮説」と「次に入れる差分」に限る。
`fix-has-diff` は、修正主張と差分ゼロの同時成立を機械的に止める。

## 完成宣言の必須欄

```markdown
- 症状: （ユーザーの言葉のまま）
- 症状測定: （修正前の数値 → 修正後の数値）
- 確認環境: （ユーザーと同じ URL・ポート）
```

## Stop

確認停止: 症状を数値化する方法が分からない。ユーザーの環境を再現できない。
差し戻し: 代理症状への言い換え / 不在証明 / 差分ゼロの修正主張 / 架空キャプチャ。
