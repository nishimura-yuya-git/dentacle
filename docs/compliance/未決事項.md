# 監査を通すために人間が決めること

正本は `src/contracts/complianceAssets.contract.ts` の `COMPLIANCE_PENDING_DECISIONS`。
推奨は案であり、承認ではない。画面に年数や「準拠済み」を書いてはならない。

ガイドラインは「何年保存せよ」と一律には書いていない。
機関が運用管理規程と契約で年数・期限・同意を定めることを求める。

| ID | 決めること | 推奨案 | 監査での使い方 |
|---|---|---|---|
| access_log_retention_years | ログイン監査・操作ログの保存年数 | 5年 | 運用管理規程に「5年保存。改ざん防止。運営のみ閲覧」と書く |
| patient_seed_retention | 種まきの保持と契約終了後の削除期限 | 利用中は保持。終了または削除指示から90日以内に削除 | 診療録の法定5年と混ぜない。Dentacleは診療録を持たない |
| overseas_processing_consent | 国外保存（シンガポール）の書面同意 | データ処理契約に所在地を書き、医院管理者が同意する | 所在地を隠すと落ちる。同意記録を残す |
| dpa_signature | データ処理契約の署名 | `データ処理契約案.md` を法務確認のうえ締結 | 案だけでは受託契約にならない |
| guideline_review_signoff | 突合表の合格／対象外と承認者 | `ガイドライン突合.md` を突合し、氏名と日付を残す | これが終わるまで準拠済みは出さない |
| incident_report_deadline | 事故の医院への報告期限 | 覚知後すみやか。例: 24時間以内 | 手順書に期限を入れて契約へ写す |

## 決め方

1. 上の6つを、医院（または法人）と Dentacle 運営で会議する。
2. 決めた値を契約と運用管理規程に書く。
3. コードの `approvedValue` は、人間が承認したあとだけ埋める。
4. 突合の合格判定と署名が揃ってから、準拠済みの表示を検討する。
