# PROJECT_MEMORY 要詰め監査コマンド（Memory Tighten）

## ゴール

打ち合わせ議事録や決定事項を入れた `PROJECT_MEMORY.md` について、**まだ精度が足りない箇所**を機械検出し、次の2つを出す。

1. 開発側用の要詰めレポート
2. **お客さまへそのまま送れる確認文**（番号付き）

`PROJECT_MEMORY.md` は自動編集しない。提示 → 先方回答／社内確定 → `/project-memory-learn` で反映、の流れを守る。

## 既存との違い

| コマンド | 役割 |
|---|---|
| `memory:candidates` / session リマインド | 差分から「足す？」候補 |
| `/project-memory-audit`（本コマンド） | MEMORY 本文から「詰める」候補 ＋ 先方確認文 |
| `/project-memory-learn` | 人間承認後の追記だけ |
| `/report-to-client` | 開発完了報告文（本コマンドとは別） |

## 実行ステップ

### STEP 1: 監査を実行する

```bash
pnpm run memory:audit
```

必要なら JSON でも確認する。

```bash
pnpm run memory:audit -- --json
```

### STEP 2: チャットに2部構成で出す（省略禁止）

必ず **A（開発用）→ B（お客さま送付用）** の順で出す。B はコピペして送れる完成文にする。

---

#### A. 開発側用（社内）

```markdown
## PROJECT_MEMORY 要詰めレポート（社内）

### サマリー
- critical: N
- high: N
- medium: N

### 優先して詰める箇所（最大 8 件）
1. [severity] 節名 — 何が薄いか — MEMORYに書くべき具体項目
2. ...

### 理解レポート §6 への転記案
- 該当項目: ...
- 要確認: critical/high の要約
```

---

#### B. お客さま送付用（完成文・番号＋質問のみ）

**そのままメール／チャットに貼れる文章**として出力する。各項目は次の1行形式だけにする。

```text
1. （質問の内容）
2. （質問の内容）
3. （質問の内容）
```

ルール:

- `質問:` / `お願い:` / `ご回答:` / 選択肢 / 【確認】見出しは付けない。
- 1番号 = 質問文1つ。それ以外のサブ項目を足さない。
- 専門用語（SSoT、RLS、Hard Boundary、プレースホルダ等）は使わない。
- critical / high を優先し、最大 **8問**。medium は必要なときだけ末尾に足す。
- audit 結果に無い確認は作らない（推測で質問を増やさない）。
- 冒頭（件名・あいさつ）と結び（返信のお願い）は短く付けてよい。

```markdown
件名: 仕様確認のご依頼（開発を進める前に決めたい点）

○○様

お世話になっております。
開発を進める前に、下記についてご確認・ご回答をお願いできますでしょうか。

1. 金額や在庫など、ズレたら困る業務はどれか。関連する画面名もあれば教えてください。
2. 売上や件数などの数字は、どの画面の表示を正としますか。
3. 単価や条件をあとから変えたとき、過去の確定済みデータも自動でやり直してよいですか。

ご回答いただけましたら仕様に反映して開発を進めます。
何卒よろしくお願いいたします。
```

出力時の手順:

1. `memory:audit` の critical / high を、上記の「番号. 質問文」に書き換える（最大8。余る枠は削る）。
2. 社内レポートの finding と番号の対応表を B の直後に小さく付ける（先方には送らない）。

```markdown
### 社内対応表（送らない）
1. → PROJECT_MEMORY §x.x / finding id
2. → ...
```

### STEP 3: ユーザーに確認してもらう

- 送付前に、ユーザーが文面を読んでから送る。
- AIが推測でプレースホルダを埋めない。
- 先方回答または社内確定後、反映は `/project-memory-learn`。

## 検出するもの（機械）

1. プレースホルダ残存（`[業務コアA]` `[関数名・ファイル名]` 等）
2. テンプレ表・空に近い節
3. 決定文なのに関連ファイル / テーブル導線がない節

## 禁止

- `PROJECT_MEMORY.md` をこのコマンドだけで書き換えること
- 会話ログだけを根拠に「薄い」と断定すること
- critical を無視して実装完了とすること（業務コアを触る作業では特に）
- お客さま文面に内部用語（SSoT、RLS、Hard Boundary、プレースホルダ）をそのまま並べること
- 先方に送る文面へ社内対応表を混ぜること
